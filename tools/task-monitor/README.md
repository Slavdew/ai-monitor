# task-monitor — прототип панели задач

Замысел и разбор — в каталоге задачи task-monitor (`PLAN.md`, `ANALYSIS.md`, `reviews/`); задачи ведутся вне
репозиториев, у владельца — `<tasks_root>\task-monitor`. Запуск: `start.cmd` или
`python server.py` → http://127.0.0.1:8770. Python 3.12 stdlib, Node — только для хука keepwarm.

## Устройство

- `config.default.json` — умолчания (в git). Личное: `config.local.json` (в .gitignore) =
  `{"settings": "D:/где-угодно/settings.json"}`, этот файл перекрывает умолчания поверх.
- Источник данных — `collect(cfg, src, ctx) -> dict` и необязательный `ACTIONS {имя: fn(cfg, src, args)}`.
  Ядро — `monitor/sources/tabs.py`; остальное — модули `modules/<имя>/` (`module.json` + `source.py`):
  sessions, claims, usage, keepwarm, board. Манифест: `name`, `api` (= `CORE_API` ядра), `version`, `title`,
  `after` (чей `ctx` нужен), `every_sec` (свой поток), `settings` (умолчания; поверх — `sources.<имя>` конфига,
  `enabled: false` — выключить). Ещё каталоги — `module_dirs`; одно имя дважды — ошибка, кроме `replaces`.
  Сломанный модуль не валит панель: ошибка в `task.py modules` и `state.sources.core.modules`; 5 ошибок
  подряд — пауза 10 мин; `POST /api/core/reload` — пересобрать реестр. Новый раздел = модуль + вид в `web/app.js`.
- `server.py` — цикл сборки раз в `tick_sec`, `GET /state.json`, SSE `/events` (номер ревизии
  при изменении), `POST /api/<источник>/<действие>`.
- `web/app.js` — `patch()` по ключам: перерисовывается только изменившаяся строка, порядок —
  по стабильным полям. Новый вид — запись в `views()`.
- `task.py` — CLI для модели и человека; пишет `task.json` в каталоге задачи. `task.py -h` — 15 строк,
  `task.py help set|batch|links|questions|api|agent` — по теме. Одна грамматика правки `ключ=значение`:
  `set T N status=… note=… after=3,4 text=…` (пункт), `set T priority=1 stage=…` (задача),
  `set T related+=B docs+="Название::путь"` (`+=` `-=` `=`, элементы через `;`); `show T` — открытые пункты с
  номерами. Ответ — `ok` / `ok пункт N`, ошибка — одна строка `ошибка: …` в stdout, код 1. Номер пункта
  проверяется в одном месте (`tabs.item`, `1 ≤ N ≤ всего`) — и для CLI, и для страницы. Прежние формы
  (`plan`, `note`, `after`, `reword`, `link`, `set T поле значение`) работают как синонимы, в help не показаны.

## Источники сейчас

| источник | откуда | токенов модели |
|---|---|---|
| `tabs` | корни вкладок: каталог с `task.json` / `HANDOFF.md` / `README.md`; шапка HANDOFF; родитель — `links.parent` или каталог-предок | 0 |
| `sessions` | `~/.claude/sessions/<pid>.json`, mtime транскрипта; привязка: `session` в HANDOFF, затем cwd | 0 |

## Токены модели: рубильник и журнал

- `model` в конфиге — всё, что тратит токены: `enabled` (общий рубильник) и флаги функций
  (`cli` — вызовы `task.py` агентом, `keepwarm` — пинги прогрева, гасятся через `ALL.off`). Выключенное
  не ломает панель: вкладки, сессии, лимиты собираются без модели всегда. Новая функция с токенами —
  проверка `model_on(cfg, 'имя')` и флаг в `config.default.json`.
- Журнал `<state_dir>/calls.jsonl`: каждый вызов CLI и действие со страницы — кто (agent, если есть сессия:
  `TASK_SESSION`, `--sid` или `CLAUDE_CODE_SESSION_ID`; иначе human), сессия, команда, время, размер ввода
  (со stdin `batch`) и вывода (≈ токены ÷ 3), текст ошибки (`err`). Сводка: `python task.py stats [--days 7]`
  — с последними ошибками.
- Зависимости плана: `plan_mode` (`sequential` по умолчанию) и `after` у пункта (`task.py set T 5 after=3`);
  задачи — `links.blocked_by`. Сервер считает состояние: готов / ждёт / можно параллельно.

## Установка на машину

`py install.py [--board home] [--clean <settings.json проекта>]` — копирует навыки task-monitor,
session-board, handoff в `~/.claude/skills`, добавляет в `~/.claude/settings.json` хуки
UserPromptSubmit (`task.py hook`, `session-board.js`), разрешение на `task.py` и `SESSION_BOARD`
(доска машины без `.dev.env`). Повторный запуск безопасен.

## Доска объявлений (`modules/board`)

Вкладка «Доска»: действующие объявления всех `%LOCALAPPDATA%/1c-ib-queue/*.board` (формат и срез
последних — как в навыке session-board) и форма «Объявить» от лица `sources.board.owner`. Пишет
через `Say-Board.ps1` навыка (`sources.board.skill`), формат не дублируется. `sources.board.default`
— доска машины, видна и пустой.

## Вопросы владельцу (`monitor/questions.py`)

Вопрос — пункт плана `status=wait`, `q=true` (в процент и очередь работ не входит): `task.py ask T
"вопрос" [--note совет] [--opt A --opt Б]` (вариантов 2–4); похожий открытый вопрос отклоняется (`--force`).
`wait` у обычного пункта не ставится — только у вопроса. Владелец отвечает в поле под
вопросом — черновик (`draft`, агенты не видят) сохраняется сам; «Зафиксировать ответы» отдаёт все черновики
задачи: `answers[]` в пункте, `state_dir/answers.json` (ждут подтверждения), строка в `events.jsonl`.
Агенту: хук UserPromptSubmit `task.py hook` — молчит, если нечего; полный текст — раз на сессию и только
по задачам этой сессии (вопрос задан ею — `by` в пункте, её захват, `session` в шапке HANDOFF, `cwd` хука в
каталоге задачи), остальные — строкой «ещё ответов в других задачах: N»; напоминание о неподтверждённых — раз
в 5 вводов или 10 минут (отметки и счётчик — `state_dir/seen/<sid>.json`). Строки ответа — с готовой командой
(`ack a 5 done`). `task.py watch [--task T]` для Monitor, `task.py unseen [--mine]`; учёл — `task.py ack T N
done` (подтвердить и закрыть; пункт без ответа — ошибка). Флаг `model.questions` выключает хук.

Просьбы владельца — пункт `req=true` (`task.py req T "просьба" [--note …]`): блок «Ваши просьбы» над
планом и «просьбы: N» у задачи, пока пункт не `done`/`skip`; дальше — обычный пункт плана.

«Перефразировать проще» — галочка под вопросом и необязательный комментарий (`rephrase_draft`),
уходит той же кнопкой: в пункте `rephrase {text, at}`, в хуке — «ПЕРЕФРАЗИРОВАТЬ (…)». Агент
переписывает вопрос `task.py set T N text="…"` (прежний текст — в `was`, просьба снимается) и подтверждает `ack`.

## Скрипты вместо рук

- `task.py batch T` — пачка правок плана из stdin одной записью под замком: `# Раздел`, `+ текст | ключ=…`,
  `N ключ=значение` (`null` — убрать); ключи `text status note section who after`; ошибка в строке — не
  меняется ничего; ответ `ok пункты 9–11`.
  На странице — чипы-фильтры по статусу над планом (мультивыбор, общий для задач, `tm.pfilter`).
- `task.py api [источник действие ключ=значение …]` — любое действие из `ACTIONS` источников через
  запущенный сервер (как кнопка страницы); без аргументов — список действий. `n=` — номер пункта с 1
  (`index` — с 0, как у страницы); значения — строки, JSON только явный (`null true false […] {…}`).
- `node ui.mjs шаг …` — безголовый Edge/Chrome по CDP: `view:`, `card:`, `click:`, `type:`, `text:`,
  `count:`, `eval:`, `shot:`; строка вывода на шаг, снимки в `%TEMP%\task-monitor-ui`. Профиль
  браузера — свой на запуск, по завершении закрывается и удаляется.

## Запуск, вкладки, документы

- Один экземпляр на `port` (8770): `start.cmd` запускает значок в трее (`tray.ps1`, PowerShell +
  WinForms, без зависимостей), он поднимает сервер, если порт свободен, и держит его. Клик — открыть
  страницу; меню: «Скопировать адрес» (открыть не в браузере по умолчанию), «Перезапустить сервер», «Закрыть панель» (гасит сервер и значок). Значок серый —
  сервер не отвечает. Второй запуск только открывает страницу; `/silent` — без браузера (автозагрузка).
  Сессии свою копию не запускают. `tray.ps1` — UTF-8 с BOM (иначе PowerShell 5.1 ломает кириллицу).
- Сервер отвечает только на свой Host, POST — только со своего Origin (чужой сайт в браузере → 403).
- Вкладки с одинаковым `group` — одна кнопка, каждая вкладка — сворачиваемый раздел под ней.
- Документы задачи: `.md`/`.html` её каталога (`item.doc_ext`, до `item.max_docs`) и
  `links.docs` («Название::путь-или-url»). Файлы отдаёт `/f/<диск>/<путь>` — только из корней вкладок
  и `file_roots`; HTML — с CSP sandbox. `.md` рендерится на странице (marked + DOMPurify в `web/`),
  отдельной вкладкой — `/?doc=<путь>`.

Захват задач (`task.py next` / `release`, `modules/claims`): вкладки — `sources.claims.tabs`
(пусто — все, кроме `ideas`); живость — по реестру `~/.claude/sessions`, сессия вне реестра (другой агент,
`TASK_SESSION`) жива `sources.claims.ttl_sec` (30 мин) с продлением при каждом вызове `task.py`.
Процесс сессии сверяется по времени создания (`procStart` реестра), запись реестра пропала — сессия закрыта;
захват вне реестра, записанный до загрузки Windows, мёртв сразу.

Новая задача со страницы — «+ Задача» во вкладке «Задачи»: вид (задача или идея — поле `kind` в task.json,
«Идеи» — подвкладка по виду из всех каталогов), каталог (выбор, если каталогов больше одного; по умолчанию первый),
проект, описание, план, файлы перетаскиванием, вставкой Ctrl+V или выбором. Файлы копируются в `<задача>/files/`.
Задачи и вложения ведутся только вне git-репозиториев (владелец 27.10): каталог вкладки (`new_root`, иначе `root`)
внутри репозитория — форма его не предлагает, `POST /api/tabs/create` отказывает.

Захват ресурсов (`task.py hold <ресурс> "зачем" [--ttl 20m]` / `free` / `held`, `task.py help hold`): ИБ, стенд,
ветка. Отказ ставит в очередь. Видно чипами «Держит» / «Ждёт» у задачи, строкой в «Сессиях» и вкладкой «Занято»
(есть, пока что-то захвачено); владелец снимает повисший кнопкой (`POST /api/claims/free`, только со страницы).

Ещё не сделано: токены по задачам (token-log), отсечка по лимиту (идея `usage-guard`),
обёртка `tm` вместо полного пути к `task.py`.
