# handoff — передача работы между сессиями

Три слоя, у каждого свой режим записи. Handoff трогает только два первых.

| Слой | Файл | Запись |
|---|---|---|
| Текущее | `HANDOFF.md` задачи | перезапись по разделам, ≤ 80 строк |
| История | `JOURNAL.md` рядом (имя может задать CLAUDE.md проекта; в DpiShell — `STATUS.md`) | только дописывать, запись ≤ 8 строк |
| Правила проекта | `CLAUDE.md` проекта, `rules/`, память | грабли, доступы, запреты — не сюда, а туда; handoff ссылается |

Где лежит HANDOFF: аргумент → строка `handoff:` в CLAUDE.md проекта → `docs/HANDOFF.md`
репозитория → на работе каталог задачи `<AI_ROOT>\tasks\<номер> <тема>\HANDOFF.md`. Путь с
пробелами — в кавычках. Нет файла — создать по шаблону; есть чужой файл с тем же именем, не
handoff, — остановиться и спросить.

## Процедура

1. **Таймеры и захваты.** `CronList`: таймеры `keepwarm:` и пробуждения соседей снять
   (`CronDelete`) — новая сессия их ID не узнает; что должно пережить сессию — в поле `timers`.
   Захваты на доске сессий, очередь ИБ — снять или записать в «Живое».
2. **Собрать факты командами, не по памяти:** `git status --short`, `git log --oneline -1`,
   `git log --oneline @{u}..` (что не отправлено), `ListAgents` (соседи), запущенные процессы и
   фоновые агенты этой сессии, worktree агентов (`git worktree list`).
3. **Обновить HANDOFF.md** по шаблону: каждый раздел заменить, не дописать. Старое содержимое
   раздела — в журнал, если оно ещё правда и ценно, иначе выбросить.
4. **Дописать журнал**: одна запись за сессию (дата, имя сессии из `ListAgents`), метки
   `сделано:` (коммиты), `решение:` + `почему:`, `отвергнуто:` + `почему:`, `не проверено:`,
   `владелец:` (дословно). Грабли, пойманные второй раз, — сразу в `CLAUDE.md` проекта или память,
   в журнал — одной строкой со ссылкой.
5. **Проверка перед сдачей** (ниже). Не прошла — доделать, не сдавать.
6. **Сообщение пользователю** — по-русски, формат в конце. Кандидаты в память — списком после него,
   только если есть.

## Шаблон HANDOFF.md

Обязательные поля и разделы помечены `*`. Раздел без содержимого — одно слово `нет`, не пропуск:
пустой «Не проверено» читается как «всё проверено».

````markdown
---
task: dpishell            # * номер/имя задачи; подзадача — через родителя: 123456/2
project: DpiShell         # * группа в мониторе задач
status: active            # * active | blocked | waiting-owner | done
updated: 2026-10-24 18:40 # * локальное время
anchor: b8b5184           # * коммит, на который опирается текст; «что изменилось» = git log b8b5184..HEAD
branch: master            # * ветка или detached
next: выпуск роутера 0.2.3 после «да» владельца   # * одна строка
resume: Продолжаем работу по <dev>\dpishell-private\docs\HANDOFF.md   # * команда для новой сессии
session: ai-e4            # имя сдающей сессии
timers: нет               # таймеры, которые должны пережить сессию, или «нет»
journal: STATUS.md        # если журнал называется не JOURNAL.md
---

# <Задача> — передача

## Start here *
1–4 шага новой сессии, по порядку, с командами: что прочитать (ссылками), что сверить
(`git status` против «Состояния», `ListAgents`, состояние стенда), кому написать.

## Состояние *
3–10 строк: сделано с прошлой передачи (коммиты), что не закоммичено (полный список своих файлов,
чужие — одной строкой), что не отправлено и почему, что сломано. Не повторять то, что лежит в
журнале, — ссылаться на дату записи.

## Слова владельца *
Дословно, в кавычках, с датой: разрешения с условиями, запреты, требования к результату.
Пересказ искажает; «мне кажется» и «может быть» — не распоряжение, пометить как сомнение.
Решения владельца с его причинами — тоже сюда, если они ещё действуют.

## Не проверено *
Что выдано за готовое, но не прогонялось вживую: где, как проверить, чем опасно. Или `нет`.

## Живое *
Процессы, стенды, фоновые агенты (ветка/worktree, что делают, как узнать, что закончили),
соседние сессии (имя из `ListAgents` + папка + тема; имена меняются после перезапуска — искать по
теме), таймеры, захваты. К каждому — «если жив: …; если нет: …».

## Открытые вопросы *
Ссылка на место вопросов (plan board, `docs/owner-questions.md`) и номера открытых. Полученные
ответы — не здесь, а в журнале как `владелец:`. Или `нет`.

## Следующий шаг *
Первый конкретный шаг с командой или файлом; что уже разрешено, что ждёт «да». Дальше — не план
(план в своём документе, ссылка), а 2–5 пунктов остатка.

## Опасно
Действия, которые в этой задаче необратимы или бьют по другим (push = выпуск; общий индекс git;
прокси владельца). Одной строкой каждое, со ссылкой на правило в CLAUDE.md проекта.

## Ссылки
Разборы, ТЗ, план, прошлые решения — путь и одна строка, что внутри. Без содержимого.
````

## Правила заполнения

- **Ссылка, не копия.** Содержимое файлов, код, списки метаданных, планы — не переписывать.
  Исключение — слова владельца и первая строка ошибки: их цитировать.
- **Команды целиком**, с путями, как их вводить: `powershell -NoProfile -File C:\…\router-sh.ps1
  <файл>`, не «скрипт роутера».
- **Секреты** — только «задан / не задан» и путь к файлу-источнику. Никогда значение, даже
  частично; ключи подписи — путём.
- **Непроверенное помечать явно** в том месте, где оно упомянуто, а не только в разделе.
- **Не писать:** грабли (в правила), лимиты токенов (устареют за час), число тестов без привязки к
  коммиту, что за проект и как в нём работать (CLAUDE.md проекта), историю решений (журнал).
- **Лимит:** HANDOFF ≤ 80 строк, «Состояние» ≤ 10, «Start here» ≤ 4 шага. Не влезает — значит, в
  текущем лежит история или правила: вынести.
- Язык — русский; имена команд, ветки, пути — как есть.

## Как обновлять, а не дописывать

- Разделы заменяются целиком. Новое «Сейчас» поверх старого — запрещено; если старое ещё нужно,
  оно уходит в журнал одной записью с датой.
- `anchor` и `updated` — при каждой записи. Текст, которому не веришь, сверяй `git log <anchor>..HEAD`.
- Закрытый вопрос, снятый таймер, умерший процесс — удалять, не зачёркивать.
- Раз в несколько передач: читать HANDOFF глазами новой сессии и выкидывать всё, что она уже
  узнает из CLAUDE.md проекта.
- `status: done` — HANDOFF остаётся с «Start here: задача закрыта, см. журнал от <дата>» и
  ничем больше.

## Проверка перед сдачей

Пройти по пунктам, не по ощущению. Любой «нет» — исправить.

- Новая сессия выполнит «Start here» и первый шаг, не задав ни одного вопроса?
- Каждая ссылка — существующий путь? (`Test-Path` / `ls` по сомнительным.)
- «Состояние» совпадает с `git status` прямо сейчас?
- Все фоновые агенты, процессы, таймеры из этой сессии либо в «Живом», либо сняты?
- Соседи, которые ждут от нас сообщения, предупреждены (`SendMessage`), их имена в «Живом»?
- Слова владельца — цитаты с датой, не пересказ? Разрешение с условием — вместе с условием?
- «Не проверено» заполнено честно, включая то, что сделали агенты и не прогонял сам?
- Нет секретов, грабель, планов, содержимого файлов?
- ≤ 80 строк; шапка заполнена, `updated` — сейчас, `anchor` — текущий HEAD?
- В журнале запись этой сессии с `решение:`/`почему:` для каждого решения дня?

## Продолжение («Продолжаем работу по <путь>»)

1. Прочитать HANDOFF целиком; журнал — только записи после `anchor` или те, на которые ссылается
   «Start here». Прошлые разборы — по мере надобности.
2. **Свежесть.** Что менялось в каталоге задачи (корень репозитория, иначе папка HANDOFF) позже
   самого HANDOFF:
   ```powershell
   $h = Get-Item '<путь HANDOFF.md>'; $root = '<каталог задачи>'
   Get-ChildItem $root -Recurse -File | Where-Object {
     $_.LastWriteTime -gt $h.LastWriteTime.AddMinutes(5) -and
     $_.FullName -notmatch '\\(\.git|\.handoff|bin|obj|node_modules)\\' -and
     $_.Name -notin 'JOURNAL.md','STATUS.md' -and $_.Extension -ne '.log' } |
     Sort-Object LastWriteTime | Select-Object LastWriteTime, FullName
   ```
   Журнал исключён: он пишется сразу после HANDOFF. Имя журнала — из поля `journal:`.
   - Есть хоть один файл кода (`.cs .js .ts .py .ps1 .sh .bsl .go` и т. п.) или изменённых файлов 5 и
     больше — **спросить пользователя** одним вопросом, показав список (до 15 строк): «После handoff
     менялись N файлов, из них код: …. Перепроверить все факты HANDOFF по текущим файлам или
     сверить только перечисленное?» До ответа фактам из HANDOFF о затронутых файлах не верить.
   - Меньше — без вопроса: сверить с HANDOFF только эти файлы.
   - В репозитории даты после `checkout`/`pull` — время операции: список сверить с
     `git log <anchor>..HEAD --name-only` и `git status --short`; файл, которого нет ни там, ни
     там, — ложная тревога.
   - В журнал строкой: `свежесть: N файлов, код: да/нет, выбор: всё/список`. Порог временный,
     подбирается по этим строкам.
3. Выполнить «Start here». Минимум: `git status` против «Состояния», `git log <anchor>..HEAD`
   (что изменилось, пока текста не было), `ListAgents` и одна строка соседям «я новая сессия
   <тема> (по HANDOFF)», проверка «Живого».
4. Расхождение HANDOFF с реальностью — реальность права; расхождение записать в журнал.
5. Таймеры по правилам проекта (keepwarm — по `keepwarm.md`), если работа продолжается.
6. Первый ответ пользователю: состояние в 3–5 строках и первый шаг. Не переспрашивать то, что в
   «Словах владельца»; не считать HANDOFF разрешением на действия, которые ждали «да».

## Сообщение после handoff

Путь — полный, как записан. Причина — по поводу: «по запросу», «по окончании работы на сегодня»,
«по указанию keepwarm», «перед сжатием контекста», «перед перезапуском». У `/restart` своё
сообщение — в его скилле.

````
---

⚠️ **Handoff обновлён <причина>:** `<полный путь HANDOFF.md>`
Кэш сессии остынет около <ЧЧ:ММ, через час>. Команда для новой сессии:
```
Продолжаем работу по <полный путь HANDOFF.md>
```
````

Связанное: `compact-instructions.md` рядом — инструкция сжатия контекста и хуки; `rules/keepwarm.md`;
скилл `restart`; разбор — `docs/handoff-design.md`.
