# Инструкция для сжатия контекста (compact)

Текст ниже — раздел для CLAUDE.md (применяется и к `/compact`, и к автосжатию, см. «Как подключить»)
и короткий вариант для аргумента `/compact`. Проверено по докам 2026-10-24, разбор —
`docs/handoff-design.md`, раздел «Compact».

## Раздел для CLAUDE.md — вставлять как есть

```markdown
# Compact instructions

Сводка — для продолжения этой же работы без переспросов. Пиши по-русски, разделами ниже, в этом
порядке; пустой раздел — слово «нет». Ссылка вместо содержимого везде, кроме цитат владельца и
первых строк ошибок.

## Задача и слова владельца
Что делаем и зачем — 2–3 строки. Требования, разрешения и запреты владельца — дословно, в кавычках,
с условиями («можно X, но только после Y»). Пересказ запрещён; сомнение («мне кажется») пометить
как сомнение, не как указание.

## Решения и причины
Каждое принятое решение + почему именно так. Отвергнутые варианты — одной строкой с причиной
отказа, чтобы не пробовать снова. Грабли этой сессии: симптом → причина → что делать.

## Состояние
Ветка, последний коммит, что не закоммичено (список файлов), что не отправлено и почему. Точные
пути всех файлов, которые правили или создали. Команды, которые работают, — целиком, с путями.
Ошибки — первая строка дословно + как починили или что не помогло.

## Фоновое и соседи
Запущенные процессы, фоновые команды и агенты (что делают, ветка/worktree, как узнать, что
закончили), таймеры (`CronList`: ID, расписание, зачем), соседние сессии (имя из `ListAgents`,
папка, тема, что от нас ждут). Путь к HANDOFF.md задачи и время его последнего обновления.

## Не проверено
Что сделано, но не прогонялось вживую; что сделали агенты и не проверял сам.

## Открытые вопросы
Вопросы владельцу (где заданы) и уже полученные ответы. Вопросы к соседним сессиям.

## Следующий шаг
Первый шаг с командой или файлом; затем 2–5 пунктов остатка. Что разрешено, что ждёт «да».

Выкидывать: содержимое прочитанных файлов (оставить путь и одну строку, что там); пройденные тупики
(оставить вывод одной строкой); длинные логи и выводы тестов (оставить итог: «N тестов зелёные на
<коммит>», первую строку падения); промежуточные версии текстов и кода; рассуждения.
Секреты — никогда: только «задан / не задан» и путь к файлу.
```

## Короткий вариант для `/compact`

Когда нужен один раз без раздела в CLAUDE.md:

```
/compact Сохрани дословно слова владельца, решения с причинами и отвергнутое, точные пути и команды, первые строки ошибок, фоновые процессы/агенты/таймеры/соседей по именам, непроверенное, открытые вопросы и следующий шаг с командой. Содержимое файлов замени путями, тупики — выводами, логи — итогами.
```

## Как подключить к автосжатию

По докам раздел читается из CLAUDE.md корня проекта и после сжатия перечитывается с диска
(`context-window#what-survives-compaction`). Аргумент `/compact` при автосжатии пуст
(`PreCompact.custom_instructions = null` для `auto`), поэтому автосжатие управляется **только**
разделом в CLAUDE.md. Автосжатие бывает трёх видов, все `auto`: по порогу (`autoCompactWindow`,
`/autocompact`), при ошибке лимита, и idle-сжатие перед остыванием часового кэша (`idleCompaction`).

1. Один источник — этот файл. В `~/.claude/CLAUDE.md`: `@<библиотека>/skills/handoff/compact-instructions.md`
   не годится (подтянет и эту обвязку) — импортировать нужно только блок раздела. Проще: скопировать
   блок в `~/.claude/CLAUDE.md` и считать его копией библиотеки (как остальные переносы, README).
2. **Проверить один раз** — доки описывают только CLAUDE.md проекта, пользовательский не упомянут:
   в черновой сессии с десятком действий выполнить `/compact` без аргумента и посмотреть, вышла ли
   сводка разделами из блока. Нет — класть блок в CLAUDE.md каждого проекта (или `@`-импортом из
   файла с одним этим блоком).
3. Правила с `paths:` и вложенные CLAUDE.md после сжатия теряются до следующего совпадения — блок
   туда не класть.

## Хуки

`PreCompact` умеет только блокировать сжатие; контекст он не добавляет, модель в нём не участвует,
а блокировка `auto` при уже случившейся ошибке лимита роняет запрос (`hooks#precompact`). Поэтому
«хук, который сначала обновляет handoff» невозможен; обновление HANDOFF перед *плановым* `/compact` —
шаг процедуры скилла `handoff`, не хука. Полезны два других события:

- **`PostCompact`** получает `compact_summary` — сохранить в каталог задачи бесплатная страховка:
  даже плохая сводка остаётся на диске, монитор задач может её показать.
- **`SessionStart` с матчером `compact`** — единственный способ *добавить* текст после сжатия
  (`hooks-guide#re-inject-context-after-compaction`): напомнить путь HANDOFF и обязательную сверку.

`~/.claude/settings.json` (не проверялось запуском; `node` — потому что PowerShell на каждый
хук стоит около секунды, см. скилл session-board):

```json
{
  "hooks": {
    "PostCompact": [
      { "matcher": "manual|auto",
        "hooks": [ { "type": "command", "command": "node \"<путь>/tools/handoff/save-compact.js\"" } ] }
    ],
    "SessionStart": [
      { "matcher": "compact",
        "hooks": [ { "type": "command", "command": "node \"<путь>/tools/handoff/after-compact.js\"" } ] }
    ]
  }
}
```

`save-compact.js`: читает JSON со stdin, пишет `compact_summary` в
`<каталог задачи или cwd>/.handoff/compact-<ГГГГММДД-ЧЧММСС>.md` (каталог задачи — из строки
`handoff:` в CLAUDE.md проекта, иначе `cwd`); ошибки гасит, код возврата 0.

`after-compact.js`: печатает в stdout одну строку — она попадёт в контекст:
`Контекст сжат. Перед следующим действием: HANDOFF задачи — <путь, если найден> (обновлён <время>);
сверить git status, CronList, ListAgents; слова владельца — только из сводки и HANDOFF, не
додумывать.` Ничего не блокирует, код возврата 0.

Оба скрипта — в `tools/handoff/` библиотеки, когда владелец подтвердит подход; пока их нет.

## Что остаётся делать модели вручную

- Перед плановым `/compact`: обновить HANDOFF.md по скиллу `handoff` (шаги 1–5), потом сжимать.
  Автосжатия это не касается — потому и нужен раздел в CLAUDE.md.
- После любого сжатия: не доверять сводке в части «Состояние» — сверить командами (`git status`,
  `CronList`, `ListAgents`), расхождения записать в журнал.
