# task-monitor — задачи в панели владельца

Агент пишет в панель **одной короткой командой**, не правя и не читая `task.json`. Решённое панель прячет сама.

- `task.py` = **`tm`** (обёртка, ставит `install.py`); если `tm` не найдена — `python <repo>/tools/task-monitor/task.py`
  **полным путём, без `cd … &&`** (так совпадает разрешение) и дальше в этой сессии — так же.
  T — id или каталог задачи, N — номер пункта с 1.
- Свой `server.py` не запускать: сервер один на машину; не отвечает — CLI всё равно пишет в файлы.

| что | команда |
|---|---|
| задачи / пункты | `ls [--all]` · `show T [--all]` — `N статус текст` |
| новая задача | `new <каталог> --title … --goal … --plan "п1" "п2"` |
| пункт | `add T "текст" [section=… after=3]` → `ok пункт N` |
| правка пункта | `set T N status=doing\|done\|skip note="…" after=3,4 text="…"` |
| поля задачи | `set T priority=1 stage="…" health=ok\|risk\|blocked next="…"` |
| связи, документы | `set T related+=B docs+="Название::путь"` (`+=` `-=` `=`) |
| пачка правок | `batch T` из stdin — `task.py help batch` |
| вопрос | `ask T "вопрос" --note "совет" --opt A --opt Б` |
| просьба владельца | `req T "его словами" --note "где ведётся"` |
| ответ учтён | `ack T N done` |

Ошибка — одна строка `ошибка: …` с допустимыми значениями. Подробно: `task.py help set|batch|links|questions|api|agent`.

## Правила

- Один пункт — одна мысль; сменилось — сразу `set`, не копить. Разбор или отчёт — `.md` в каталоге задачи
  (панель покажет сама), в план — короткий пункт, в чат — суть и ссылка.
- **Этапы = разделы плана** (`section=`), «осталось» панель считает из статусов — держать их честными.
  `priority`: 1 срочно … 4 потом. Стоит из-за внешнего — `blocked="…"`; риск — `health=risk risk="в чём риск"` (владелец видит причину по щелчку); вопросы владельцу — не blocked.
- Текст — Markdown: пункты и вопросы строчные, **одно главное жирным**, пути и команды — в `код`.
- **Без персональных данных клиентов** (ФИО, телефоны, ИНН, адреса, суммы договоров) в названиях, планах,
  вопросах и на доске: всё это уходит в контекст модели и коллегам. Клиент — номером обращения CRM.

## Вопросы и просьбы

- Вопрос — одна строка; варианты `--opt` (2–4), совет — `--note`. В чат: «добавил N вопросов в задачу X».
  Похожий открытый вопрос `ask` отклонит — дополнить его `set T N note=…`.
- Ответ приходит хуком «Панель задач: ответы владельца» с готовой командой: учесть, поправить план, затем
  `ack T N done`. «ПЕРЕФРАЗИРОВАТЬ» — `set T N text="проще"`, затем `ack T N` (вопрос ждёт дальше).
  Черновики владельца (`draft`) не читать.
- **Перед итоговым сообщением — `unseen --mine`**: каждый ответ, пришедший за время работы, применить (поправить
  план, сделать решённое) и подтвердить `ack T N done` (синоним — `принят T N done`) — тогда он не всплывёт снова; затем проверить ещё раз,
  пока новых нет. Итог — одним сообщением: результат работы и коротко по ответам (принят /
  что сделано по нему). Stop-хука нет намеренно (владелец 27.10): итог не должен дробиться; ответ, пришедший во
  время вывода, владелец укажет сам.
- **Каждую просьбу или поручение владельца — сразу `req`**; сказанное мимоходом — тоже, разобрать, а не исполнять
  молча. Разбор — `doing`, сделано — `done` с `note`, не будем — `skip` с причиной.

Захват: **начиная работу над задачей — `take T`** (ответы владельца по ней хук покажет этой сессии целиком;
без захвата — только строка «ещё ответов: N»), `next [--tab T]` — взять первую свободную, `release` — отпустить. Общий ресурс (ИБ 1С, стенд, ветка) — перед
работой `hold <ресурс> "зачем" [--ttl 20m]`, после — `free`; отказ «занято» — не трогать ресурс (`help hold`).
