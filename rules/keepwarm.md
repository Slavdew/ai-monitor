# Поддержание кэша сессий (keepwarm) — локальная проба

Проба с 22.10.2026, только на этой машине, в общий репозиторий не уходит. Схема и оценка —
`<AI_ROOT>\ideas\Поддержание кэша сессий (keepwarm).md`. Действует только в основной сессии,
не во вложенных агентах.

Кэш промпта живёт час. Таймер будит сессию раз в 30 мин, хук
`<AI_ROOT>\tools\keepwarm\keepwarm-gate.js` решает по её журналу, что делать: сессия отвечала
меньше 25 мин назад — гасит запрос, к модели он не уходит; молчит — до срока из запроса таймера
пинг, после срока handoff (или только снятие таймера, если в запросе «без handoff»). Внеурочно
срока нет — «один прогрев»: первый простой — пинг, второй — handoff.

Рабочий день начинается первым вводом за сутки и длится 9 ч (`keepwarm.config.json`). Первый ввод
вне окна 07:00–11:00, суббота или воскресенье — весь день внеурочный. Без часов внеурочно и после
конца дня команда выдаёт «один прогрев на <дата>»; ставить так же.

## Поставить

Сессия начала разработку по БТ (ТЗ, доработка, отладка) — поставить таймер по умолчанию без
вопроса и сказать об этом одной строкой. Вид задачи — строка «Проект:» в карточке из CRM
`<AI_ROOT>\tasks\<номер>*\<номер>.md`: «Бизнес требования» — ставить, «Обращения в ИТ» — не
ставить; карточки нет — по сути работы (папка «Обращение - …» — обращение). Разбор, вопрос,
разовое действие — не ставить, даже по БТ. Сначала `CronList`: таймер `keepwarm:` уже есть —
второй не ставить.
По просьбе пользователя — в любой сессии: `/keepwarm [часы] [true|false]` (скилл `keepwarm`),
«включи keepwarm», «держи кэш»; `/keepwarm off`, «выключи keepwarm» — снять.

Текст запроса — вывод команды (без аргументов — до конца рабочего дня с handoff; часы — от
текущего момента; `false` — без handoff):

```
node "<AI_ROOT>\tools\keepwarm\keepwarm-gate.js" --prompt [часы] [true|false]
CronCreate(cron="13,43 * * * *", recurring=true, prompt=<вывод команды>)
```

Таймер живёт, пока открыта сессия, но не дольше 7 дней.

## Настройка дня

«Сегодня работаем до ЧЧ:ММ» (и в любой сессии, не только по БТ) — выполнить и ответить одной
строкой из вывода:

```
node "<AI_ROOT>\tools\keepwarm\keepwarm-gate.js" --day-end ЧЧ:ММ
```

День становится рабочим до этого времени, даже внеурочный или выходной. Сегодняшние таймеры без
часов во всех сессиях («(конец дня)», «один прогрев на <сегодня>») переходят на новый срок со
следующего срабатывания; таймеры с явными часами не меняются. Пересоздавать таймеры не нужно.
Время раньше текущего команда отвергает — переспросить.

## Запрос таймера

Указание `keepwarm-gate` выполнять как есть: пинг — ровно строка из указания, без инструментов и
без продолжения прошлой работы; handoff — по тексту указания, без вопросов. Указания нет (хук не
сработал) — ответить одной строкой «🔄 Обновление кэша», без инструментов.

## Снять

`CronDelete` таймера `keepwarm:` по ID из ответа `CronCreate` (ID не найти — сначала `CronList`).
Перед handoff — снимать первым, чтобы между handoff и предупреждением не стояли блоки таймера:

- закрытие ТЗ — триггеры из `tz-journal.md` → «Закрытие» («сливаем», «влей ветку», «разработка
  закончена», «закрой ТЗ», «ТЗ выполнено / отменено»);
- «работа закончена», «сессию можно закрывать», работа уходит в другую сессию;
- «на сегодня всё» при незавершённой задаче — снять, затем handoff (скилл `handoff`, аргумент —
  каталог задачи `"<AI_ROOT>\tasks\<номер> <тема>"` в кавычках), причина в сообщении — «по
  окончании работы на сегодня»;
- handoff по указанию хука.

Пользователь вернулся и продолжил разработку в сессии, где таймер снят после handoff, — поставить
заново.
