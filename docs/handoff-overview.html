## 2026-10-24 · ai-e4
сделано: b8b5184 трей без мерцания; 4a1c2e0 тесты UiGuard
решение: иконку трея перерисовывать по таймеру, а не по событию
почему: событие приходит пачкой при смене DPI — мерцание
отвергнуто: подписка на WM_DPICHANGED — на части мониторов не приходит
не проверено: два монитора с разным масштабом
владелец: «мерцание — блокер беты»

Метки ищутся grep: grep -n "отвергнуто:" STATUS.md — чтобы не пробовать то же снова.

Процедура передачи

  1. Таймеры и захваты. CronList → снять keepwarm и пробуждения (CronDelete); что должно пережить — в timers.
  2. Факты командами, не по памяти. git status --short, git log --oneline @{u}.., ListAgents, git worktree list.
  3. HANDOFF.md: каждый раздел заменить. Старое, если ещё ценно, — в журнал.
  4. Журнал: одна запись с метками. Грабли второй раз — сразу в CLAUDE.md проекта.
  5. Проверка по чек-листу ниже. Любое «нет» — доделать.
  6. Сообщение: путь, причина, время остывания кэша, команда для новой сессии.

Проверка перед сдачей

  • Новая сессия выполнит «Start here» без вопросов?
  • Каждая ссылка — существующий путь?
  • «Состояние» совпадает с git status?
  • Агенты, процессы, таймеры — в «Живом» или сняты?
  • Соседи предупреждены, имена в «Живом»?
  • Слова владельца — цитаты с датой и условиями?
  • «Не проверено» честно, включая работу агентов?
  • Нет секретов, грабель, планов, содержимого файлов?
  • ≤ 80 строк, updated — сейчас, anchor — HEAD?
  • В журнале решение:/почему: на каждое решение дня?

Продолжение

  • HANDOFF целиком; журнал — только после anchor.
  • Свежесть: файлы новее HANDOFF. Есть код или их ≥ 5 — спросить: перепроверить всё или только список.
  • «Start here»: git status, git log <anchor>..HEAD, ListAgents, проверка «Живого».
  • Расхождение — права реальность, записать в журнал.
  • HANDOFF — не разрешение на то, что ждало «да».
