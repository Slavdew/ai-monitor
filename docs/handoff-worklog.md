## Решения

- **Один `HANDOFF.md` на задачу**, перезапись по разделам, ≤ 80 строк — вместо
  `handoff-<время>.md`. Почему: «версии» одного состояния никто не читает, команда продолжения
  меняется, монитору нужен стабильный путь. Решение владельца.
- **Три слоя:** HANDOFF — текущее; `JOURNAL.md` — история, только дописывается, метки
  `сделано: / решение: / почему: / отвергнуто: / не проверено: / владелец: / свежесть:`;
  грабли и доступы — в CLAUDE.md проекта / rules / память. Почему: в DpiShell четыре «Сейчас»
  друг над другом, грабли «ломалось 6 раз» жили в handoff.
- **Обязательные разделы**, пустой — словом «нет»: Start here, Состояние, Слова владельца
  (дословно, с датой), Не проверено, Живое (процессы, агенты, таймеры, соседи — с «если жив / если
  нет»), Открытые вопросы (ссылка), Следующий шаг с командой.
- **Шапка YAML под монитор задач** (согласована с его сессией): `task` — стабильный id как в
  task.json, `title`, `project`, `status` (только здесь), `updated` — ISO 8601 со смещением,
  `anchor` — коммит для `git log <anchor>..HEAD`, `branch`, `next`, `resume`, `session` — полный
  sessionId из `$env:CLAUDE_CODE_SESSION_ID`, `timers`, `journal`, `spec`, `infobase`. Связи задач —
  в task.json, не в шапке.
- **Проверка свежести при продолжении:** файлы каталога задачи новее HANDOFF (без журнала, `.git`,
  `.handoff`, `bin`, `obj`, `node_modules`, логов). Есть код или ≥ 5 файлов — вопрос владельцу
  «перепроверить всё или только список»; итог строкой в журнал. Порог временный, решение — по
  практике. Предложение владельца.
- **Из `handoff-message` перенесено:** порядок выбора места (на работе — каталог задачи, не
  репозиторий), кавычки в путях, план — ссылкой на `design.md`, «сожми сессию» = `/compact`,
  сообщение после handoff — первая строка слово в слово (её ловит Stop-хук монитора), причины.
- **`restart` убран:** он сводился к снятию таймера и другому сообщению. Триггеры «/restart»,
  «перезапусти контекст» теперь у `handoff`, второй вариант сообщения — с `/clear`.
- **Язык документа — русский** и на работе; правило `handoff-message` требовало английский.
- **Compact (по code.claude.com):** автосжатие управляется только разделом `# Compact instructions`
  в CLAUDE.md; `PreCompact` только блокирует, поэтому «хук, обновляющий handoff перед сжатием»
  невозможен — это шаг скилла перед плановым `/compact`. Вместо него — `PostCompact` (сводка в
  `<каталог HANDOFF>/.handoff/compact-<время>.md`) и `SessionStart:compact` (напоминание: путь
  HANDOFF, сверить git status / CronList / ListAgents).

## Отвергнуто

- `handoff-<время>.md` на каждую передачу — см. выше.
- Хук `PreCompact` — не умеет добавлять контекст.
- Развилка в keepwarm «ждёшь фоновую операцию — не делай handoff» — владелец счёл перестраховкой.
  Если сессии начнут уходить в handoff, ожидая агента: гибрид — хук ищет в журнале фоновый запуск
  без уведомления и только тогда добавляет развилку.
- Поиск HANDOFF по любым путям в журнале — на живом журнале подхватил путь из вывода теста. Ищется
  только во вводе пользователя и в Write/Edit модели.

## Проверено

- `handoff-hook.js`: три способа поиска HANDOFF, запасной каталог, мусор на входе — на временных
  каталогах; на журнале живой сессии — ложного срабатывания нет.
- Команда свежести — на `<dev>\dpishell-private`: 0 файлов после HANDOFF; со сдвигом на сутки —
  14 (`.md`, `.html`, `.ps1`), мусора сборки нет.
- `keepwarm-gate.js` — только `node --check`.
- `$env:CLAUDE_CODE_SESSION_ID` совпадает с `sessionId` в `~/.claude/sessions/<pid>.json`.

- Раздел compact из `~/.claude/CLAUDE.md` (доки говорят только про CLAUDE.md проекта) — нужна
  тестовая сессия с `/compact`.
- Подсказка keepwarm о handoff в живом срабатывании таймера.
- Личный скилл `handoff` против проектного с тем же именем в vika — кто кого перекрывает.
