# ai-monitor — обзор

Для тех, кто решает, подключать ли панель: что она даёт, как ей пользоваться и как подстроить под себя.

## Что это

Локальная веб-страница (http://127.0.0.1:8770) и набор навыков для Claude Code. Через них агенты
ведут свои задачи (план, вопросы, документы, передачу между сессиями), а вы видите все задачи сразу,
отвечаете агентам и управляете приоритетами. Облака и внешних сервисов нет: всё работает на вашем
компьютере, данные лежат в обычных файлах.

## Что это даст

Пригодится, если с Claude Code работаете много, особенно в нескольких сессиях параллельно.

| Без панели | С панелью |
|---|---|
| что важнее, что осталось и на каком этапе задача — держать в голове | приоритет, остаток работы и этап каждой задачи видны на одной странице |
| вопросы агента теряются в длинном чате | вопросы собраны в одном месте; ответ доходит до нужной сессии сам |
| новая сессия начинает с пересказа | продолжает одной командой по файлу передачи (handoff) |
| две сессии берут одну задачу или одну базу | видно, кто что взял; второй встаёт в очередь |
| расход подписки виден только в терминале | лимиты 5 часов и недели — на странице |
| агент снова и снова повторяет одни и те же ошибки | сторож ловит частые ошибки до выполнения, журнал показывает повторы |

Панель почти не тратит токенов: данные собирают скрипты и хуки, модель пишет только то, что знает
лишь она, и короткими командами.

**Когда не нужна:** одна короткая сессия в день, задачи не переходят между сессиями.

## Что нужно

- Windows (трей, автозагрузка и пути `%LOCALAPPDATA%` — виндовые), Python 3.12, Claude Code.
  Сторонних библиотек нет.
- Право держать на своей машине фоновый процесс, отвечающий только на localhost.

## Как начать

1. `py tools\ai-monitor\install.py --tasks <каталог задач>`. Установщик ставит версию в
   `%LOCALAPPDATA%\ai-monitor`, навыки — в `~/.claude/skills`, хуки — в `~/.claude/settings.json`,
   значок в трее и автозагрузку. Повторный запуск безопасен, откат — `install.py --use <версия>`.
2. Перезапустить сессии Claude Code, чтобы подхватились навыки и хуки.
3. Открыть страницу (щелчок по значку в трее). Задачи появляются, когда агент заводит их сам
   (`am new …`), или через «+ Задача» на странице.

## Как пользоваться каждый день

- **Агент** ведёт задачу командами `am` (навык ai-monitor подсказывает ему когда): пункты плана,
  статусы, вопросы вам, просьбы, документы.
- **Вы** смотрите страницу: «Ждут вас» — вопросы и действия для вас, «Задачи» — план и этапы,
  «Сессии» — кто над чем работает. Отвечаете в поле под вопросом, «Зафиксировать ответы» — и при
  следующем вашем вводе агент получит ответ.
- **Конец дня или смена сессии:** «сделай передачку» — агент пишет HANDOFF.md. Новая сессия
  продолжает по команде «Продолжаем работу по <путь>».

## Что видно на странице

| Раздел | Что показывает |
|---|---|
| Ждут вас | вопросы агентов и действия, которые нужны от вас |
| Задачи | цель, план с этапами и зависимостями, просьбы, документы задачи |
| Канбан | задачи по состоянию |
| Сессии | какие агенты сейчас работают и над какой задачей |
| Лимиты | расход подписки: 5 часов и неделя |
| Доска | объявления сессий друг другу (сменилась ветка, занята база и т. п.) |
| Занято | захваченные ресурсы и очередь; повисший захват снимается кнопкой |
| Идеи | отложенные замыслы отдельно от рабочих задач |

Закрытое и решённое по умолчанию скрыто, но открывается одним щелчком вместе с обоснованием.

## Навыки и инструменты

| Навык или инструмент | Что делает | Когда срабатывает | Ставит |
|---|---|---|---|
| **ai-monitor** (навык) | агент ведёт задачу короткими командами `am` / `task.py` | при решении, новом пункте плана, вопросе вам | install.py |
| хук ответов | при вашем вводе передаёт агенту ваши ответы; если их нет — молчит | каждый ввод, почти без затрат | install.py |
| **handoff** (навык) | передача работы следующей сессии: состояние, ваши слова дословно, что не проверено, следующий шаг | «сделай передачку», конец дня | install.py |
| хуки сжатия контекста | сохраняют итог сжатия рядом с HANDOFF и напоминают сессии, где он | при сжатии контекста | вручную |
| **session-board** (навык) | доска объявлений между параллельными сессиями | при смене общих условий: настройки, ветка, состояние базы | install.py |
| **keepwarm** (навык и хук) | держит кэш сессии тёплым в короткие паузы, после долгого простоя сам делает handoff | таймер раз в 30 минут; проба | вручную, выключен по умолчанию |
| сторож вызовов (guard.py) | останавливает частые ошибки: чтение секретов, push в выпускную ветку без подтверждения, общий индекс git | перед вызовом инструмента | install.py |
| журнал граблей (pitfalls.py) | записывает ошибки инструментов с постоянным кодом; по повторам видно, какое правило добавить сторожу | после ошибки инструмента | install.py |
| строка состояния | передаёт панели лимиты подписки | при каждом ответе модели | install.py, если своей строки нет |

## Как подстроить под себя

Порядок работы автора — только умолчание. Ваше — в личном файле настроек (путь — в
`config.local.json`), там только отличия от `config.default.json`: каталоги задач, вкладки, пороги,
включение и выключение разделов. Всё, что тратит токены, выключается одним переключателем.

Свой раздел данных — модуль (`module.json` + `source.py`) в своей папке, подключённой в настройках.
Общий модуль можно заменить своим или выключить. Своё поведение агента — свой навык рядом с общими.
Общий код и навыки без согласования с командой не правятся: порядок — в [extending.md](extending.md).

## Почему так устроено

- **Почти без токенов.** Панель, которая тратит заметную долю лимита, теряет смысл.
- **Локально и в файлах.** Нет сетевого сервера, базы данных, учётных записей. Задача — каталог
  с `task.json`, HANDOFF и вложениями; всё читается глазами и работает без интернета.
- **Задачи вне репозиториев.** Рабочие заметки и вложения не попадают в git вместе с кодом.
- **Только документированные интерфейсы Claude Code.** Ничего, что может нарушать условия
  использования: ни внутреннего реестра сессий, ни токена подписки.
- **Один писатель.** Задачи меняются только через `task.py` (под замком и с проверкой), поэтому
  параллельные сессии не портят файлы друг другу.
- **Модули.** Каждый раздел — отдельный модуль; сломанный модуль не роняет панель.

## Безопасность

Страница доступна только с этого компьютера и отвечает только своему адресу. Запросы с чужих сайтов
отклоняются. Документы открываются только из каталогов задач, HTML — в песочнице. Секреты не
выводятся. Персональные данные клиентов в задачи не пишутся (правило в навыке).
