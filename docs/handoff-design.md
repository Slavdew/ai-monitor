## Что есть в чужом скилле и чего нет

Есть и стоит оставить: принцип «ссылка, не копия» (C, шапка и «What NOT to write»); «Verification
State» с исходами passed/failed/not-run/unknown; «resume не выдаёт полномочий» («Next Steps»,
«Resume work»); запрет секретов и дампов MCP.

Нет (закрывает своя структура, в скобках — раздел шаблона):
- решений с причинами и отвергнутых вариантов — только «Open Questions» (→ журнал, метки
  `решение`/`отвергнуто`);
- граблей — вовсе (→ правило «второй раз — в rules/память», в handoff только ссылка);
- живого состояния кроме git: процессов, фоновых агентов, таймеров, соседних сессий (→ «Живое»);
- дословных требований пользователя — лишь «reference the user's request» (→ «Слова владельца»);
- признака устаревания кроме `When` (→ якорный коммит в шапке + `git log <якорь>..HEAD`);
- лимита объёма и правила «обновлять, не дописывать»: каждый handoff — новый файл
  `handoff-<время>.md`, старые копятся, `Previous handoff` тянется цепочкой (M:14, M:29);
- проверки перед сдачей «следующая сессия стартует без вопросов» (→ чек-лист);
- английский язык документа (M:16) — дома практика русская (H, R целиком), и память
  `briefs-for-agents` объясняет, почему экономия на языке мнимая.
Разделы CF/CFE, MCP 1С, OpenSpec — мёртвые вне работы, M:36–39 это уже признаёт.

## Слои

Одна куча не работает: долгоживущее (что за проект, как работать) засоряет текущее, журнал
вытесняет сводку, грабли повторяются. Делим по сроку жизни:

| Слой | Файл | Живёт | Кто читает | Правило |
|---|---|---|---|---|
| Правила проекта | `CLAUDE.md` проекта, `rules/`, память | месяцы | каждая сессия автоматически | грабли, команды доступа, запреты («не пушить без да»). Handoff сюда только ссылается |
| Текущее | `HANDOFF.md` задачи | до следующего обновления | новая сессия целиком | перезаписывается по разделам, ≤ 80 строк, шапка машиночитаема |
| История | `JOURNAL.md` задачи (в DpiShell эту роль уже играет `STATUS.md`) | вечно, только дописывается | по `grep` и от якоря | запись ≤ 8 строк: сделано (коммиты), `решение:` + `почему:`, `отвергнуто:`, `не проверено:` |
| Вопросы владельцу | plan board / `docs/owner-questions.md` | до ответа | владелец | HANDOFF даёт ссылку и номера открытых; ответы — в журнал как `решение владельца:` |

Почему не один файл с разделами: журнал растёт без предела и его нельзя перезаписывать, HANDOFF
обязан перезаписываться — разные режимы записи. Почему не файл на сессию (`handoff-<время>.md`,
как в C и M): команда продолжения меняется каждый раз, старые файлы никто не читает, а монитору
задач нужен «последний зарегистрированный handoff» по стабильному пути (PLAN.md:24–28).

## Стыковка с монитором задач

PLAN.md требует: команда продолжения по последнему handoff (:24), ключевые значения, по которым

сессией, это предложение, не договор.

## Compact — что проверено по докам

Проверено (code.claude.com, 2026-10-24):
- `/compact [instructions]` — аргумент есть (`docs/en/commands`, строка таблицы `/compact`).
- Раздел `# Compact instructions` в CLAUDE.md корня проекта описан (`docs/en/costs#manage-context-proactively`);
  `docs/en/how-claude-code-works#when-context-fills-up` называет его способом управлять тем, что
  сохраняется при автосжатии («add a "Compact Instructions" section to CLAUDE.md»). Прямой фразы
  «применяется и к auto» нет, но раздел описан именно в абзаце про автоматическое заполнение.
- После сжатия заново читаются с диска: CLAUDE.md корня проекта и **нескопированные** правила (без
  `paths:`), память, план plan mode, до 5 последних файлов; контекст, добавленный хуками раньше,
  **сжимается вместе со всем**; фоновые команды и агенты продолжают работать, о них напоминается
  (`docs/en/context-window#what-survives-compaction`). Правила с `paths:` и вложенные CLAUDE.md
  теряются до следующего совпадения (`docs/en/memory#instructions-seem-lost-after-compact`).
- `PreCompact`: матчеры `manual`/`auto`; вход `trigger`, `custom_instructions` (для `auto` —
  `null`); **умеет только блокировать** (exit 2 / `decision: block`), контекст не добавляет, stdout
  модели не виден. Блокировка `auto` при уже случившейся ошибке лимита роняет запрос
  (`docs/en/hooks#precompact`). Значит «хук, который сначала обновляет handoff» невозможен: хук —
  шелл, модель в нём не участвует.
- `PostCompact`: вход `compact_summary` — сводку можно сохранить в файл (`docs/en/hooks#postcompact`).
- `SessionStart` с матчером `compact`: stdout/`additionalContext` попадает в контекст после сжатия
  (`docs/en/hooks-guide#re-inject-context-after-compaction`). Это единственный документированный
  способ что-то *добавить* после сжатия.
- Автосжатие: порог — `autoCompactWindow` / `/autocompact`, выключатель `autoCompactEnabled`;
  есть **idle-сжатие** незадолго до истечения часового кэша (`idleCompaction`,
  `docs/en/prompt-caching#compacting-the-conversation`) — оно тоже `auto`.

Не проверено: работает ли раздел «Compact instructions» из `~/.claude/CLAUDE.md` (документ говорит
только про корень проекта; пользовательский CLAUDE.md грузится тем же слоем, вероятно работает) и
через `@`-импорт. Проверка — одна: положить, выполнить `/compact` в черновой сессии, посмотреть,
соблюдён ли формат сводки. Переменная `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` в доках не найдена — не
опираться.

Следствия для дизайна: инструкция compact живёт в одном файле `compact-instructions.md` и
подключается в CLAUDE.md (общий через `~/.claude/CLAUDE.md`, после проверки); хук `PreCompact` не
ставим; ставим `PostCompact` (сводка в файл задачи — бесплатная страховка) и `SessionStart:compact`
(напоминание: путь HANDOFF, `git status`, `CronList`, `ListAgents`). Обновление handoff перед
ручным `/compact` — шаг процедуры скилла, не хука.
